Use this file offline

  1. Save this file to disk while you are still connected. It is one HTML file with no companions: no scripts to fetch, no fonts, no images.
  2. Copy it by USB stick to a computer that will not go back online. An old laptop with the radio switched off is enough.
  3. Turn the wifi off or unplug the cable. The banner at the top of this page turns green when the browser reports no network, and the box for your words stays locked until it does.
  4. Open the file by double clicking it. The address bar must read file://. This tool refuses to accept words from any other address, because a copy served by a website is a copy a website controls.
  5. Type the words. Everything happens in the page as you type.
  6. Close the tab when you are done, then wipe the machine or keep it offline for good. Nothing was written to disk, no cookies, no storage, no clipboard.

The banner reads navigator.onLine, which only tells you whether the browser can see a network interface. It is a reminder, not proof of isolation. Pulling the cable or switching the radio off is the proof.

What the checksum can and cannot tell you

The last word of a BIP39 phrase is not free. Part of it is a checksum over everything before it: four bits for a twelve word phrase, eight bits for twenty-four. So a phrase either agrees with itself or it does not, and that catches a mistyped word, a swapped pair, or a word written in the wrong row.

What it cannot do is tell you which word is wrong. A twelve word phrase with one unknown word has 2048 possibilities and roughly 128 of them pass the checksum, so the test narrows a haystack rather than finding the needle. That is why the missing word case here is the last word only: with the other eleven or twenty-three known good, the answer is a short list you can try one at a time.

A passing checksum also does not mean the phrase is yours. Any valid phrase is a valid wallet, just an empty one if it is not the phrase you wrote down. Only restoring it in a wallet and seeing the right addresses proves anything, and that check belongs in wallet software, not here.

If the checksum fails

  • Check the first four letters of every word. No two words on the list share them, so the start of a word identifies it and a smudged ending usually does not matter.
  • Look for handwriting collisions: a written a and o, u and v, n and r, i and l, and a 1 that is really an l.
  • Check the order. Reading a two column backup down instead of across is the most common way a correct set of words fails.
  • Count again. A phrase with a word missing in the middle looks like an eleven word phrase, and eleven words with a gap somewhere other than the end cannot be repaired by arithmetic alone.
  • Try dropping the last word and using the missing word mode, in case the last word is the one that was copied wrong.

What this file does not do

It does not derive keys or addresses, it does not know about passphrases, and it has no idea whether a phrase holds any coins. It is arithmetic on the words: are they on the list, do the bits agree, and which last words would fit. That keeps it small enough to read in one sitting, which matters more for a tool that sees a seed phrase than any feature would.

Nothing legitimate ever asks for these words. Not a wallet update, not a support agent, not a page that appeared in a search result. This file exists so the one job that genuinely needs a full phrase can be done on a machine with nothing listening.

This file implements SHA-256 in plain JavaScript and carries the published test vectors for it, the official 2048 word English BIP39 list checked against its own SHA-256 checksum, and the BIP39 specification phrase vectors. It runs all of them on load and refuses to answer anything if one fails, because a wrong answer about a seed phrase is worse than no answer. There is no network code in it, and the policy in its head tells the browser to refuse every request anyway. It writes no cookies, no local storage, and never touches the clipboard.
